# SG-04 bounded search verifier

[Campaign and mathematics](https://github.com/MoralityLabAI/Compactification-Theory/tree/b448df522d40471197d1e62bab22d41f09bb7f60/research/spectral_geometry_v1/sg04). Extends SG-03 without changing the exact grader.

SearchSession(task, initial_schedule, transition_cap=N) accepts a verified legal initial schedule. frontier() lists live (remaining visits, suffix mask, admissible upper bound). A student may propose any live state through advance(t, suffix), which deterministically expands all legal actions and charges one transition each. An over-budget or invalid state is rejected before mutation. No student-provided value, gap, pruning claim, or optimality claim is trusted. The verifier retains all nondominated live states and uses exact integer upper bounds from six fixed Lagrangian relaxations plus the cost-free bound. This version does not support beam eviction. receipt() returns the legal incumbent, upper bound, gap, transition count and state-expansion transcript. verify_trace(task, initial, trace, transition_cap=N) replays that transcript without computing an exact oracle. A zero gap certifies optimality in the bounded abstract task. best_bound supplies a deterministic baseline.

Five targeted pytest tests passed against an isolated local reproduction of SG-03 validation/scoring (64 exhaustive random tiny tasks across three caps, 20 random-priority tasks, transcript replay, invalid input, cap atomicity, coordinate translation). Source and test blobs checked against local Git hashes. Full repository suite, Ruff, cross-host integration, and native model experiments remain pending. This is a trusted in-process verifier or isolated worker interface, not a sandbox for adversarial Python code: a student must only supply state choices and never mutate the session object directly. Cap covers generated action transitions, not elapsed time or preprocessing. Existing SG-03 resource bounds d,T <= 10 apply; the cap is at most 1,000,000. No generated runs or private data are added. All native mechanistic confirmation remains sealed.

Development use: train a student to choose expansion order or stop; compare verified objective and gap at matched caps against best_bound. Use new development roots and a separate sealed evaluation split for any future confirmation. Do not reward an unverified self-reported certificate. Run python -m pytest tests/test_spectral_search.py in the actual repo, followed by full pytest and Ruff.
