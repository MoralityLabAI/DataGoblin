# SG-06: verified adaptive reasoning expenditure (development)

Runnable CPU pilot using the pinned SG-03/04/05 verifier modules. Install the repository with its neural extra, then run `OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python training/rlt_gym/sg06_spectral_allocation/sg06.py`. Results are generated next to the script; keep generated results and model weights outside the DataGoblin repository. All generator seeds are exposed development fixtures, not confirmation roots. No model downloads, network requests, or paid inference.

All policies select the live state with highest certified upper bound. They allocate either a complete search expansion or one reverse coordinate sweep from zero (at most one proposal per state key). The 12-dimensional observation contains the certified gap, competing frontier bound, remaining visits, suffix size, weak-minus-current bound, frontier size, action count, lambda, consumed caps and attempted status. All arms use the same caps (2048 transitions, 24 proposals, 80 decisions), feasible initial schedule (best of three heuristics) and fallback to the sole legal action if either action is unavailable. Thus expand is expansion priority, not strictly expansion-only at transition exhaustion. Recurrent weights are tied across decisions in a 12-state tanh RNN. MLP has 169 parameters; recurrent and shuffled RNN have 313 each. This is a small RNN allocation pilot, not a canonical TRM or native recurrent language model.

Offline imitation teacher compares one legal action on independent session copies by immediate gap/mean-frontier-potential decrease plus incumbent improvement divided by a deterministic work proxy (generated edges for expand, 3*t for dual). This is not measured-time RL or an optimal long-horizon teacher. 48 independent training roots yield 304 eligible labels (240 dual); labels shuffled within roots for the matched recurrent control. 120 full-batch Adam updates per model; one training seed per architecture. No tuning on the 48 new exposed evaluation roots. Three planted regimes, 36 tasks of d=8,T=6 and 12 of d=9,T=7. Full verifier event replay checks each certificate and exact SG-03 integer optimum is an external evaluation reference only.

Timing uses one CPU thread, process_time_ns, randomized arm order within root and budget. Timed interval includes initial heuristic, session construction, inference, all verifier work and final receipt; excludes offline training, exact reference and post-hoc independent transcript replay. Work-cap comparison measures CPU time to a certificate or cap. Soft 20 ms CPU deadline checked between atomic actions, not a hard preemptive cap; all overshoots retained. An outlying random-policy overshoot reached 24.20 ms beyond deadline. Single host, one timing repetition. No cross-host speed guarantee or native mechanistic confirmation.
