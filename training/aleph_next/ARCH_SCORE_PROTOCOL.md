# Read-only evaluation partition

This operational supplement freezes before creation of the fresh seed. Computational units are independent frozen model checkpoints. `arch_scoring.py prepare` verifies the entire main training registry, all file hashes, paired stream identity and the preregistered source contract before creating one private integer. Every scoring worker then constructs the same panel with `architecture_lab.evaluation_rows` and calls the same `evaluate` procedure, native schedule and same-weight comparator schedules used by the monolithic scorer. Each individual checkpoint writes an atomic, custody-bound result. `collect` requires all units and emits the original score representation and promotion receipts. This changes process scheduling only. Reruns reuse the same sealed draw.

For one worker use `architecture_lab.py score` as registered in the main protocol. For two workers, invoke `arch_scoring.py prepare --out OUT`, then use `arch_scoring.py run --out OUT --seeds 137 163` and `arch_scoring.py run --out OUT --seeds 191` on distinct, released cores, followed by `arch_scoring.py collect --out OUT`. All commands use the local bounded runner. Preserve the private seed and per-checkpoint parts locally.
