## What earns admission

The producer renders the public instruction and canonical JSON premises. The response starts after the literal delimiter `\nAnswer\n` and ends with a newline. The tokenizer encodes the entire transcript in one call, with automatic special tokens disabled. The mask accepts only tokens starting at or after the response boundary. The exporter checks exact decode round-trip, binds the token IDs and mask to a detached verifier receipt, and inserts the verified root and family in the existing SQLite custody index. The replay independently parses each prompt, recomputes the label, re-encodes the transcript, checks the registry-bound files, and can invoke Lean again. [Producer](curation_tasks.py) · [Independent solvers and kernel driver](curation_check.py) · [Native export and replay](curation.py)

The duplicate keys reflect the mathematical task. State programs use their prefix transformations and initial state. Operators use the whole finite function table. Horn proof trees erase atom, rule and premise-order renamings when identifying an equivalent causal shape. Machine pairs use minimized reachable automata with canonical rooted state numbers. Allocation graphs use the path length and the branch lengths incident on each endpoint. Lean collapses exact statement templates differing only in numeric literals. This conservative rule also drops some legitimate distinctions among numerals. These keys cover the listed transformations. They do not decide general theorem equivalence or identify all shared sublemmas.

Every native Lean prompt comes from the two hash-pinned training files. Among 36 historical training goals, 32 had a closed action with an acceptable original kernel receipt and eight distinct statement templates survived. Another 49 examples use applications of named array, list and bitvector lemmas in the extracted open-source Lean core. The exporter verifies the referenced source declarations and records the installed source-file hashes, Git revision, Apache-2.0 license hash and new kernel receipt. The other 68 Lean examples are original generated goals about predicate congruence or ordered transitivity. The complete pack comprises 6,853 original project examples, 49 Lean-core-derived examples and eight historical project training examples. Project-generated material is tagged for internal DataGoblin training. The external core license and its copyright notices are preserved. ## Supplemental tournament data

The external allocator then supplied a train-only archive with 48 true Nat/List obligations on 24 source lineages. The materialized supplement adds **45 roots and 16,019 processed tokens**. Twenty-three composition tasks ask for a locally checkable rewrite path. Twenty-two separate allocation tasks ask for the fastest affordable option from four historic measured quotes. Allocation charges the eligibility gate, solver and kernel time, and the prerequisites for reusing a prior proof. Its prompt presents measurements and acceptance status. It trains accounting on observed options. Prediction of the fastest solver before measurement is a separate task.

The exporter verifies each step against both sides of the same rewrite schema, its substitution and its unchanged outer context. It reproduces the original Lean 4.19 singleton source exactly from the complete path and checks its compiler receipt. All 23 retained proof certificates compiled again under Lean 4.28 with an axiom inventory check. Edits preserving the same normal-form denotation, variable-renamed equivalents and siblings of an existing lineage are collapsed. The cost audit keeps cases with at least two affordable accepted single-action options under 4.98112 seconds and three kernel calls. Every nanosecond-quantized winner matched the original floating-point route calculation. Twenty-five proof candidates collapsed and one cost slate lacked two affordable options.

The two skill objectives share the source lineage and denotation digest. Their public prompts, response types, root IDs and answer masks differ. The supplement supplies 9,890 composition positions and 6,129 allocation positions, including 4,283 and 512 packed target positions respectively. The first shard remains independently keyed. The supplemental manifest is `15d2c9432041a3bbbe129dd3572049830fe6baedd8b03439f55bf779810113d9`. [Supplemental exporter and verifier](tournament_admission.py)

## Reproduction

Run from the DataGoblin checkout. Supply the original mixed pilot pack, official Lean 4.28.0 distribution including sources and license, and the recipe's pinned tokenizer. The output location must be new for a build. The admission and replay paths run offline.

```sh
python training/aleph_next/candidate01/curation.py build --pack runs/placement/mixed --lean ../aleph-next/lean-4.28.0-windows/bin/lean.exe --tokenizer ../aleph-candidate01/tokenizer.json --out ../aleph-candidate01/verified --count 1536
python training/aleph_next/candidate01/curation.py verify --pack runs/placement/mixed --lean ../aleph-next/lean-4.28.0-windows/bin/lean.exe --out ../aleph-candidate01/verified --recompile
python training/aleph_next/candidate01/curation_custody.py --verified ../aleph-candidate01/verified --retrospective ../aleph-state15/verified --lean ../aleph-next/lean-4.28.0-windows/bin/lean.exe --out ../aleph-candidate01/custody-verified
python training/aleph_next/candidate01/tournament_admission.py --source ../aleph-allocation/final --base ../aleph-candidate01/verified --tokenizer ../aleph-candidate01/tokenizer.json --lean ../aleph-next/lean-4.28.0-windows/bin/lean.exe --out ../aleph-candidate01/tournament-train
python -m pytest -q tests/test_candidate01_curation.py
```
