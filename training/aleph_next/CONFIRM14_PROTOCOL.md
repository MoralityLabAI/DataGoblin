# Fresh confirmation of the 14.18M dense control pair

This is a new experiment following the failed 32-update competence gate. The experimental unit for architecture is a matched training seed. A is two-pass direct recurrence and B is two-pass global constant damping with the terminal block at full strength. Both have 14,179,584 trainable parameters and 24 logical block applications. Use the six archived, native 32-update prefix checkpoints for seeds 137, 163 and 191. Match original initialization and stream within seed. The old artifacts contain weights only. Restart the optimizer in both arms and train equal numbers of steps on exactly the same ordered examples. Intermediate checkpoints may be fitted in parallel; B's scores cannot select the horizon or curriculum.

## Development and custody

Select the continuation recipe and stopping point using the direct baseline on development only. Record all failed development attempts, exact corpus/stream hashes, numeric parent and endpoint identities, supervised and processed positions, and optimizer changes. Publish the direct competence criterion before opening the fresh panels. The minimum historical 14M text check is beating the training-byte unigram; add a checked reasoning task with an actual cue comparator. Publish each domain and seed separately. Models that learn a new structured aid while failing the original task must be identified as such. Training, tuning and selection schedules have no access to the fresh text/reasoning panel or to any B confirmation score.

Before scoring, freeze the selected recipe and all six weight hashes, the held source manifests, the family specification, analysis code and statistical rule. For text, pair architectures on exactly the same target bytes within a document and use the document as the resampling unit. For reasoning, use families/independent generated roots as specified by the held reasoning protocol. Keep repeated counterfactuals and both graph-revision questions together. Record any test family that is unresolved. Confirmatory intervals are conditional on these three seeds, which are also reported individually.

## Second-slot decision

Require both candidate and reference to meet the development competence checks. Evaluate held checked macro in percentage points and text loss in nats per byte. Let T be (B NLL / A NLL) − 1 and R be (B checked success − A checked success). Negative T and positive R favor B. Use paired 2.5th and 97.5th percentiles from the specified clustered bootstrap. Require both safeguards, upper(T) ≤ .01 and lower(R) ≥ −.02. Require one of the following two improvements, with the winning metric favoring B on at least two matched seeds:

- Text route: point T ≤ −.01 and upper(T) < 0.
- Reasoning route: point R ≥ .02 and lower(R) > 0.

Require a B/A throughput ratio ≥ .90 in the separately controlled same-core training benchmark. Report time during actual fits as well. Compare to simple allowed-information reasoning cues and the text unigram. A gain against another weak model without demonstrated benchmark competence cannot promote B. A null or imprecise result keeps the slot unearned. An approved miniature architecture still requires production corpus admission, restart validation, accelerator profiling, and a separate spending decision.

## Resource calibration

Use one allowed processor, FP32 eager PyTorch, hard memory and wall limits, low priority, no accelerator, for each fit and scoring worker. The timing benchmark replays identical public original native examples and multiple fixed seed initializations through complete dense forward/backward/AdamW updates. Use counterbalanced arm order, warm both, and record elapsed wall and process CPU seconds. Use the median of within-seed paired useful-positions-per-CPU-second ratios as the primary control of architectural runtime overhead; report wall ratios and the limits of extrapolation to hardware pricing. Short arithmetic checks and report assembly may use normal CPU execution. No paid compute.
