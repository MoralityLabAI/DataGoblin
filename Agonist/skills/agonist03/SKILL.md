# AGN-03: Storyworld-to-reasoner continual curriculum

Use with Agonist/SKILL.md (taste intake and teacher custody), Agonist/skills/agonist02/SKILL.md (student uplift), and the GPTStoryworld authoring skill. The author is operator-selected Bonsai 2 27B or Inky Mini. Resolve the actual model revision, quantization, tokenizer/chat template and context limit from the local backend; do not guess identifiers, download weights, call a paid provider or start a job. Treat all teacher prose, code and causal explanations as untrusted proposals.

## Authoring ticket

Data Goblin selects a source-attributed taste seed, family ID, train/dev split, one mechanism, a target capability, intended K, and maximum budget. The teacher produces a bounded JSON object with `request_id`, `family_id`, `mechanism`, `swmd_min`, `public_metadata`, `private_sidecar_proposal`, `counterfactual`, `causal_claim`, `inductive_hypothesis`, `design_note`. Generate original fictional settings; external source text remains reference-only absent rights clearance. Keep public SWMD separate from the evaluator-side latent world law. Never put hidden truth or a future observation into an actor's prompt. The author can propose an existing whitelisted simulator adapter and typed parameters, not arbitrary executable code. Unsupported mechanics are quarantined until a trusted implementation exists.

Author in SWMD-0-MIN using the existing storyworld skill. Work one encounter card at a time; maintain an external world card, source-origin ledger and encounter index. Preserve actor-specific knowledge, declared observation channels, source dependencies, explicit budgets and credible reaction formulas. Telegraph access prerequisites and stakes. Each significant option should change attainable utility or information; show a matched superficial-cue control. Supply a one-mechanism counterfactual with matched exogenous assignment, action budget and evidence visibility. Keep K as a vector: optimal opening lookahead, receding-horizon performance, epistemic ambiguity, provenance depth, state revision and distractor burden. Require reachable endings and declared effect sizes, audit winner flips and score shifts separately. Do not inflate difficulty by adding inert variables or impossible gates.

## Verify and export

1. Pin authoring source, simulator source, seed law, observation interface, reward and intervention. Run native validator and reader playthrough for native exports; a subset SWMD audit is not engine parity.
2. Independently replay legal action sequences. Match shared public histories across compatible latent worlds. Compute exact or bounded planning ceiling, strong access-aware heuristic and random/shortcut baselines. Measure attainable opportunity, utility, false assertion and actual acquisition cost. Require paired counterfactual evidence for any purported causal effect; descriptive traces alone cannot establish it.
3. Emit immutable, source-hashed episodes. Before an action the student sees only public history and legal options. Its checked target may be an oracle action, an equivalence set of tied actions, or an outcome observed after executing a permitted action. Keep terminal scores, latent world, oracle law and paired sibling outside the acting prompt. Off-policy oracle labels are not teacher votes.
4. Create separate lanes: action/observation, belief revision and provenance, causal counterfactual, inductive conjecture/counterexample, formal statement and Lean proof-state/tactic repair. Tag every claim with evidence class: proposed, replay-checked finite, kernel-checked conditional, or independently measured learner transfer. A Lean result proves the formal contract under its assumptions, not that the narrative or real history satisfies them. Use the existing pinned LeanKernelChecker workflow, verify statement fidelity and allowed axioms, retain failed tactics; never mark a draft proof kernel-checked. A universal claim inferred from a finite sample requires a proof or explicit unresolved status. A single counterexample can reject it.
5. Curate by source-family and mechanism-family, not rendering, name, seed, action row or trace count. Hold confirmation generator families, seeds and gold state outside teacher prompts and training. Retain all rejected proposals, repeated roots, unknown labels and verifier costs. Share the existing four-presentation cap across all released views of one root. Only rights-cleared train roots with independently reviewed receipts may be promoted. Offline development fixture exports always have `training_ready=false`.

## Continual-learning loop

Begin with the exact symbolic policy and the strongest inexpensive heuristic. For a compact student, use the same tokenization, observation interface, train roots, action space and measured compute for flat and tied recurrent arms; include explicit typed memory and a matched flat-memory baseline. Test direct recurrence first; extra refinement, RLT, learned memory routing, TRM/HRM variants earn their place via fresh held-out improvement. Track processed tokens, FLOPs/updates, verifier calls and wall time separately. Keep persistent evidence pointers exact when identity is already known.

At each round, freeze a checkpoint and its corpus manifest; train from new verified roots mixed with replay from earlier families. Compare sequential-only, fixed mixture/replay, random curation and Data Goblin-selected curation at matched training budgets. Measure fresh-family complete episode success, realized utility, calibrated selective risk, verified proof completion, induction transfer to unseen counterexamples, and old-family retention on independently maintained anchors. Freeze selection rules and independent confirmation before opening test outcomes. Limit adaptation to train and designated development results. Reject a checkpoint if improvement is below the registered meaningful floor, if retention falls outside the registered margin, or if the corpus audit fails; preserve predecessor, optimizer and failed branch. Do not update weights during evaluation. Recurrent refinement within a forward pass is a separate operation from continual parameter learning.

Data Goblin chooses the next generator family using measured expected student gain per full cost (teacher tokens, verifier work and learner updates), diversity, uncertainty and an explicit exploration allocation. Use matched random and frozen heuristic controls; account for calibration overhead. First run bounded CPU fixtures, then a capped local small-model pilot if authorized. No larger pretraining release or GPU spend follows from successful wiring alone.
