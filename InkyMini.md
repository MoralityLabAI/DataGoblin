# Inky Mini through Loop Schedule Algebra

**Proposed 10B-token pair.** Train a dense Aleph with direct feedback and an otherwise identical Aleph that rereads the prelude once, halfway through its second core pass. This asks a question that matters for Data Goblin: after a model has formed a provisional answer, does a short path back to the original claim help it find a valid correction? Both models fit the existing 999,352,320-parameter design. Benchmark their 10B checkpoints under the same verifier budget, then continue the selected checkpoint to 20B. This is a new source-read experiment. The previous placement tournament remains evidence about damping.

## Reading the Inkling 2 Mini decoder

“Inky Mini” here means Thinking Machines Lab's fixed-depth **Inkling 2 Mini** release. In LoopedTransformers, the architecture record is $A=(S,\Phi,w,\rho,g,\sigma,\pi)$. The word $w$ specifies which block executes next. The registers and read/write maps specify what information reaches it. For Mini's text decoder, group the 24 physical layers into six-layer blocks $P,U,V,D$, in input-to-output order. Then $w=P(UV)^3D$. Expanded left to right this is $P,U,V,U,V,U,V,D$. There are 48 layer applications, 24 physical layers, twelve singleton layer classes and twelve classes visited three times. At the layer level, physical layer 7 occupies logical positions 7, 19 and 31 (one-based). Thinking Machines reports a sparse 26.4B model, 3.4B active parameters and 5.4B effective weight activations per token after repeated visits. These are different resource counts. [LSA-02 calculus](https://github.com/MoralityLabAI/LoopedTransformers/blob/31256abc921ae9aa500ad4fb85a167a990be0984/docs/lsa_typed_architecture_calculus_v0.md) · [Official model card](https://huggingface.co/thinkingmachines/Inkling-2-Mini)

| LSA field | Interpretation for the fixed release |
|---|---|
| $S$ | Causal token states, saved prelude output, current block state and earlier block messages. Incremental decoding also needs position and visit-specific attention-cache state. |
| $\Phi,w$ | Four block groups with two tied middle groups. Their internal decoder layers retain separate physical identities. |
| $\rho$ | Learned attention-residual reads combine available block outputs. The later passes can mix prior-pass messages with the prelude and current computation. |
| $\pi$ | Preserve the prelude across passes and expose the previous pass's middle-block outputs to the next pass. This is within the token computation; a cross-request memory would be a separate contract. |
| $g,\sigma$ | Gradient visibility and supervised loss sites are separate training fields. The inference word alone leaves those fields undetermined. The released decoder emits token predictions after the coda. |

At a block boundary, let $p=P(x)$, let $M_0$ be empty, and write $M_j=F_\theta(p,M_{j-1})$ for $j=1,2,3$. Here $F$ stands for the ordered $U,V$ computation with its internal gated reads, and $M_j$ collects middle-block outputs. This schematic preserves both input paths. The convenient shorthand $h_3=C^3(p)$ on a single endpoint loses the distinction between recovering the source and retaining a message. The authors found greater accuracy gains from middle looping than from late looping on 27 of 28 evaluations in their placement ablation. That is evidence for **where to repeat computation**. The advantage of a particular prelude read in a dense 1B model is a separate empirical question. Depth-extrapolation results from the variable-loop companion belong to that checkpoint. ## Two dense Aleph architectures

Both use the same word **$P(UV)^2H_1H_2D$**. Here $P,D$ are one layer each, $U,V$ contain five distinct layers each, and $H_1,H_2$ are two answer layers. That gives 14 physical layers and 24 logical visits. The first core pass is identical in both arms. Set $p=P(E(x))$, $h_1=V(U(p))$ and $u=U(h_1)$.

| | Aleph Direct (A) | Aleph Prelude (B) |
|---|---|---|
| Input to $V$ on visit two | $u$ | $z=\tfrac34u+\tfrac14p$ |
| Final core state | $V(u)$ | $V(z)$ |
| Readout | $H_1,H_2,D$, final RMSNorm, tied vocabulary head | Same readout |
| Architectural hypothesis | The current stream retains enough source information to repair an error | A token-aligned read of the original source helps the second half of the core revise a provisional answer |

The one changed edge reads the saved prelude at the same token position. Its coefficient is fixed at $1/4$, an experimental choice. Both arms backpropagate through all visits and through every used read path, use final next-token or masked-response supervision, and reset internal state between sequences. Each physical block has causal GQA, pre-RMSNorm and dense SwiGLU. Width is 2,048, with 16 query heads, four KV heads, core FFN width 8,960, other FFN width 8,192, vocabulary 49,152 and context 2,048. Both use RoPE and a tied embedding/head. The extra saved activation in B can affect memory or throughput even at equal parameter and visit counts. Keep RLP, SGRT/HoloArc, LDT, curation and verification outside both neural models. Inkling can propose synthetic claims; Aleph can challenge them; an independent checker decides whether a correction enters the corpus. [Dense parameter and cost ledger](training/aleph_rlt_placement/ARCHITECTURE.md) · [Trainable reference forward](training/aleph_rlt_placement/inky_pair.py)

**Why put the read in the middle?** Blending $p$ with $h_1$ immediately before the second pass is exactly first-pass damping: $(1-\beta)h_1+\beta p=p+(1-\beta)(h_1-p)$. At the internal site the two operations can differ even with affine blocks. Take $p=(0,1)$, $U(a,b)=(a+b,b)$ and $V(a,b)=(a,b+1)$. A yields $(3,3)$ and B yields $(9/4,11/4)$. Ordinary first-pass damping by $\gamma$ followed by the unmodified second pass yields $(1+2\gamma,2+\gamma)$. Matching B would require $\gamma=5/8$ and $\gamma=3/4$ simultaneously. This proves architectural distinguishability. It leaves the sign of any learning benefit open.

**Strongest cheap rival.** At the same internal site and coefficient, substitute the second pass's starting state $h_1$ for $p$. This gives ordinary damping around $U$. Before committing TPU credits, train that control in a miniature alongside A and B with paired seeds. Test unchanged claims, single-premise edits and irrelevant edits on fresh families. Measure independently verified repairs and valid witnesses, alongside byte loss. Also swap the source on frozen weights and report lost as well as gained successes. If ordinary damping explains the gains, the evidence favors the cheaper explanation. The published local placement screen gives good reason to run this check: three-pass whole-core RLT improved byte loss over direct in the miniature, yet constant damping beat RLT on text in every seed. That screen did not train B. [Placement findings](training/aleph_rlt_placement/FINDINGS.md)

## The 10B decision and the additional 10B

1. **Match the first two runs.** Freeze tokenizer, corpus and root/family split manifests. Start A and B from identical weights and use the same ordered 10B nonpadding training positions, objectives, optimizer schedule, decoder and checker budgets. Use the reference two-pass BF16 recipe and position-based LR clock. Count repeated inputs, masked targets and padding separately. Time both models on the intended TPU with identical packs. The source read must respect causal and document boundaries. [Optimizer settings](training/aleph_rlt_placement/fullscale.json) · [Packing and cursor contract](training/aleph_rlt_placement/packing.py)
2. **Bench both saved 10B checkpoints.** Primary language metric is held document-level NLL. Score Lean goals solved within four attempts, rule revisions correct both before and after an edit, verified first-fault repairs, and accepted counterexamples. Freeze a fresh author-independent panel and a meaningful checked-task gain before training. Pair scores by document, goal family or generator lineage, and use simultaneous intervals for the registered comparisons. Retain the existing guards of at most 1% relative text regression, two percentage points checked-macro regression, and 10% throughput regression. Among arms passing the guards, prefer a resolved lower language NLL on the primary endpoint. With one full-scale seed per arm this selects a checkpoint for continuation. Within a predeclared text-equivalence band, prefer a confirmed gain in verified decisions; if equivalent on both, prefer the faster passing arm, breaking a measured speed tie toward A. Unresolved intervals justify preserving both checkpoints and deferring the spend. [Selection protocol](training/aleph_rlt_placement/PROTOCOL.md)
3. **Continue only the adjudicated winner.** Restore weights, AdamW moments, scaler if applicable, RNGs, processed-position LR clock and exact pack cursor. Train on the next 10B positions and evaluate the 20B checkpoint on a second untouched panel. Total training is **30B processed positions**, with **20B on the winner**. At the operator's 55 hours and 350 credits per leg, the first decision costs about 110 hours and 700 credits. The complete plan is 165 hours and 1,050 credits, 50 over the stated balance before evaluation overhead. Tokenizer and production manifest pins, measured TPU throughput and continuation funding are still open. [Planning ledger](training/aleph_rlt_placement/fullscale.json)

The reference forward accepts `direct` and `prelude_reread` and shares a state dictionary between arms. Its tests check the exact reread location, unchanged direct logits, a tiny backward/optimizer step, segment and causal isolation, and full-size count/shape on meta tensors. Run `python -m pytest -q training/aleph_rlt_placement/test_inky_pair.py` from the DataGoblin root. Production TPU training remains a backend integration and profiling step.
