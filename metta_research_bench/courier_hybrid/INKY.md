# Source registration for the offline Inky comparator

The six skills define the Inky prompts. This auxiliary pilot instantiates them with the locally available Qwen3.5-0.8B checkpoint at the revision and SHA-256 in `inky_cpu.json`. Use text-only greedy generation without a thinking block and one CPU thread. Keep the first reply to each task. Record actual prompt tokens, generated tokens, latency, prompt and response digests, and the checkpoint identity. Model output has no verifier authority. [Pinned Qwen checkpoint](https://huggingface.co/Qwen/Qwen3.5-0.8B/tree/2fc06364715b967f1860aea9cf38778875588b17)

Score the first development score root in each topology stratum. Route tasks use the last four actions of an exact completion as the setup boundary. Public requests omit those actions and the exact continuation value. For rejection or tie tasks, the adapter selects a reachable fixture with a verified rejection or verified shortest tie and uses a typed response schema. If a root has no qualifying tie or rejection, exclude that task and count the number evaluated. Score output syntax and model performance within this small exploratory cohort. No confirmation roots are used for this comparator.

Run `inky_suite export` with the pinned model identifier and `--roots-per-family 1`. Run `inky_cpu` on the public JSONL using the local pinned weights. Run `inky_suite evaluate` with the same model identifier and root cap, the development fit directory, and the reply JSONL. The receipt compares Inky routes with deterministic MeTTa search and the development shortest-set LoopedPointer. Each controller has five native calls, including any prefix certificate, native search, macro attempt, and accepted STOP. External input and output tokens, latency, and LoopedPointer visits have separate meters.
