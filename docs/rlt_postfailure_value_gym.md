# RLT post-failure value-of-compute gym

Status: CPU-only verifier replay and calibration instrument, 2026-11-21.
This is a cross-family stopping baseline over **the seven existing
verifier-backed DataGoblin task families**. It extends the native
pretrained TRM STOP/CONTINUE campaign with a different observable
decision point.

## Decision boundary

The trained Sudoku model's logits-only stop gate decides whether to
stop *before asking the exact checker* whether its current candidate
is valid. That calibration came from BPD PR #140 and demonstrated
a real native inference saving on one Sudoku difficulty distribution;
BPD PR #141 subsequently documented one unsafe early stop at a
harder distribution.

For Lean proof attempts, MCP tool calls, and experiment/research
repair, a useful *post-check* decision occurs after a failed attempt
has produced an independent verifier receipt. The controller decides
whether another candidate/iteration is worth the extra time or
verifier call.

This gym measures the latter policy in the existing seven-family
DataGoblin suite. A failed first candidate supplies its public
task, attempted candidate and known checker code. Future correctness
remains in a separate evaluator label. A fitted ridge head predicts
whether later visits on the archived fixed-depth trajectory contain
a verified rescue.

A failed proof or tool execution need not be rerun indefinitely when
the expected marginal benefit is low. The model can choose to defer.
This design preserves the exact verifier as the final arbiter of
accepted solutions, and protects against mistaking a confident
unverified string for a proven answer.

## CPU execution

Install DataGoblin with its usual development dependencies. From
the repository root, run:

    python -m datagoblin rlt-gym make-suite \
      --seed 20261121 --per-family 4 \
      --out runs/stop-value/suite

    python -m datagoblin rlt-gym run \
      --suite runs/stop-value/suite \
      --seeds 7 --training-modes direct --modes direct \
      --depths 4 --training-depth 4 \
      --splits train calibration ordinary_test ood_test \
      --terminal-only --omit-controls --max-wall-seconds 240 \
      --out runs/stop-value/full-depth

    python -m datagoblin.training_gym.rlt_gym.postfailure_exit \
      --suite runs/stop-value/suite \
      --run runs/stop-value/full-depth \
      --depth 4 --seed 7 --mode direct --training-mode direct \
      --max-missed-calibration-rescues 0 \
      --out runs/stop-value/policy

The final command first runs the existing exact replay_run validator.
It checks the source suite, every model checkpoint, all candidate
verifier receipts and exact native trajectory reconstruction. It
refuses protected sealed_poison inputs, incomplete trajectories,
source-root duplication and mixed model settings.

The extracted decision dataset contains one first-failed candidate
decision per independent root. The existing Aleph 192D feature builder
sees only the public world, failed candidate and its already
observed feedback. The labels are whether a later attempt succeeds
within the fixed recurrence budget, computed by the independent
environment verifier.

TRAIN roots fit a regularized ridge continuation predictor.
CALIBRATION roots choose the most frugal score threshold subject to
a registered allowance for missing genuine later rescues
(default zero). ORDINARY and OOD test roots are scored once with
the preselected threshold.

Controls are (1) first verified within fixed depth,
(2) a single-check floor, (3) learned defer/continue, and
(4) a seeded random continuation policy matched to the CAL
continuation rate among failures.

## Claim limits

**All candidate trajectories have already been generated at fixed
depth.** The saved verifier-call figures are offline prefix-replay
counterfactuals. They are not actual measured savings in model
inference time. No native learned neural recurrence or direct
Inkling teacher is run in this experiment. The ridge model only
chooses whether to continue from previously generated attempts.
A later online implementation must confirm that stopping does
not alter future candidate generation or verifier timing.

The seven synthetic families and the source-root split firewall use
the existing DataGoblin task suite. The ordinary and OOD test panels
are development measurements, separate from sealed-poison tests.

DataGoblin's private GitHub Actions runner has failed before runner
setup in recent campaigns. The new tests and CLI are committed; a
fresh local execution with full replay is still needed.

## Lean, MCP and research repair adapters

Use the same post-verifier decision contract for future adapters:

- **Lean:** A failed tactic's visible kernel-rejection code, current
  proof goal and remaining check budget are valid features. A kernel
  certificate generated by a fresh, version-pinned Lean 4 environment
  is the outcome verifier. The 588 archived Lean-CGRT replay goals
  are historically exposed and explicitly training-ineligible.
  Source-root-disjoint new TRAIN proofs are needed.
- **MCP:** Tool-result status, stable API specification and visible
  feedback are legitimate observations. Correctness requires a
  reproducible task-specific external checker, a bound tool/schema
  revision, and evidence of actual state effects. A well-formed
  JSON response alone is insufficient. Treat missing authentic
  verifier receipts as unavailable labels.
- **Research repair:** Public experiment hypotheses and observable
  run outcomes can train the model to decide whether further
  checks are worth conducting. The actual hypergame evaluator
  owns its private state and transition tape. Preserve its
  expected-utility objective, control cost and source-root
  structure; do not equate success with a text matching heuristic.

Every adapter must recheck the producer's full candidate trajectory
with its own independent verifier before presenting labels to this
controller. A certified source hash, source split and root lineage
identify each training example. The precheck stopping model from
Sudoku and the postfailure value-of-another-check model are separate
decision heads. This avoids information-flow confusion when training
the eventual ALEPH-1B DataGoblin recurrent router.
