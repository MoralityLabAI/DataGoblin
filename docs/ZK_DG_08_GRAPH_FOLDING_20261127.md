## Construction

Given an independently authorized topologically sorted plan of N jobs, common
width w <= 2, N <= 32 and maximum depth D <= 32, carry a state

    z = (pc, context_hi, context_lo, R[0], ..., R[N-1]).

The context limbs encode the domain-separated SHA-256 of the complete plan;
the limbs are pinned in the circuit. The public initial state has pc=0 and
all registers zero. Allocate selectors s[j], enforce s[j]^2=s[j],
sum s[j]=1 and pc=sum j*s[j]. Since N is smaller than the field, precisely
one selector is one. The plan fixes the coefficients of every parent join,
source vector, recurrent matrix, bias and depth. Multiplication by s[j]
selects the active worker's join and coefficients. Saturate the selected
join to obtain x. Starting with h=x, run D padded recurrence passes.
At pass t, m[t]=sum_{j: depth[j]>t} s[j] is either zero or one. Constrain

    h_new = h + m[t]*(clamp(W_selected h+b_selected+x)-h).

For each output register constrain

    R_new[j]=R[j]+s[j]*(h_final-R[j]).
    pc_new=pc+1.

All initial registers and saturated outputs are bounded to [-127,127].
The saturation gadget uses the previously specified nonnegative 19-bit
slacks and complementarity equations. The largest join magnitude is
32*127; the width-two recurrent pre-clamp bound is 2*127^2+254.
All of these integer ranges are tiny relative to either Pasta field.
The plan-specific constraints and wire mapping remain identical for each
worker step. The shape is generated by trusted code, independent of advice.

Induction: at counter j the already executed registers contain their
specified outputs, and future registers remain zero. Only the active
worker reads its designated earlier parent registers. The recurrence and
depth mask determine its exact output, and the conditional write preserves
all other registers. With the pinned initial state and exactly N steps,
the terminal register file contains the complete authorized graph result.
This is a mathematical argument about the constraint relation, not a
machine-checked Lean proof or proof of Nova's implementation.

This compiles one fixed DAG into sequential IVC. It neither aggregates
independent worker proofs nor permits a worker to modify the schedule.
The circuit is specialized to the exact plan, including context, so setup
reuse across plans is limited. All terminal registers are public. No
private-input or private-model claims. The reference compiler obtains
expected terminal registers by computing them; this is appropriate for
development controls but a production relying party should authorize the
relation and accept a claimed output only after verifying its proof.

## Local execution receipt

    PYTHONPATH=src python -m pytest -q tests

105 passed in 5.09 seconds (74 prior tests plus 31 new tests).
The new cases cover 24 deterministic random graph fixtures across 1,3,8,32
workers, both widths and three seeds; check every step in both Pasta fields,
compare every output against zk_replay, require stable shape, check input/
output state linkage, reject corrupted counter/context/register/output/
selector assignments, changed authorization and a step after completion.
The native bundle serialization is checked against the same R1CS interpreter.
Tests are regression evidence, not an exhaustive proof of compiler soundness.

These are constraint generation/checking times, not cryptographic proof
times. Nova's augmented recursion circuit adds overhead. Compact JSON
statement/advice bytes respectively: 14655/1220, 51039/31345,
114272/254806. These are not proof sizes.

The padded depth mask trades additional arithmetic for fixed shape.
The all-register state costs O(Nw) state elements, and each worker step
touches all registers. A graph-frontier allocator that retires each
register after its last consumer could reduce state arity, especially for
chain-like plans, while a committed register file would allow sparse access
at the expense of authenticated memory arguments.

## Native adapter and smoke

The Rust crate under experiments/zk_dg_nova pins nova-snark=0.76.0
with default features disabled and Pallas/Vesta IPA/Pedersen commitments.
It maps the relying-party-generated sparse R1CS to Nova's StepCircuit,
uses state_in wires directly from the recursive input, allocates advice
wires, enforces all constraints and returns the designated state_out.
It checks exact expected final state for recursive and compressed proofs.
A standalone verifier rebuilds parameters from a SHA-256-pinned trusted
statement, deserializes the compressed proof with bounds and rejects trailing
bytes. The trusted statement digest must come from the relying party, not
the prover. This generic bridge does not independently establish that an
arbitrary supplied statement expresses the intended graph semantics.

Source API:
https://docs.rs/nova-snark/0.76.0/nova_snark/nova/struct.RecursiveSNARK.html
https://docs.rs/nova-snark/0.76.0/nova_snark/nova/struct.CompressedSNARK.html
https://github.com/microsoft/Nova/blob/main/examples/minroot.rs

From repository root (Rust toolchain and registry access required):

    cargo build --release --manifest-path experiments/zk_dg_nova/Cargo.toml
    PYTHONPATH=src python experiments/zk_dg_nova/smoke.py --out /tmp/nova-dg8 --nodes 8 --depth 4 --native experiments/zk_dg_nova/target/release/zk-dg-nova

Use .exe on Windows. The smoke harness checks a real separate prove/verify
process, wrong statement pin, changed expected output, trailing bytes,
truncation and mutated proof. Repeat at 1 and 32 nodes and varying maximum
depths; retain Cargo.lock and rustc version, and record setup, folding,
compression, verification wall times, proof bytes and peak RSS. A smoke
failure blocks promotion; fix compilation and test independently before
claiming any Nova results. The direct Nova version is pinned, but the
transitive lockfile cannot be generated in the current environment.
Regenerating public parameters on every verification is a development
choice; production needs a reviewed, cached, authenticated parameter/key
format and strict sandbox/resource limits.
