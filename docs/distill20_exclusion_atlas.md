# DISTILL-20: exact source-revision atlas

DISTILL-19 established packed integer selection savings at larger widths. This additive study asks whether repeated public revisions can amortize exact DP compilation for a changing exclusion from source s0. All other observed exclusions are fixed only for the current numerical atlas; a change invalidates it. Version/receipt/frame authority is always rebound from current observations and checked by the native host in native episodes.

## Factorization

For the sorted affordable candidate array after removing fixed exclusions, let L_i(c) be the maximum packed score from candidates strictly before i with cost at most c. Let R_i(c) be the analogous suffix strictly after i. When candidate i is excluded, its exact optimum score is max_{0<=c<=C} (L_i(c)+R_i(C-c)). The two subsets are disjoint, so packed membership bits cannot collide or carry into utility. This recovers the same utility and lexicographic tie rule as DISTILL-19. If the variable candidate is already fixed or unaffordable, reuse the full optimum. Build prefix rows once, walk a rolling suffix backward, and retain only the full packed score and one score per affordable variable exclusion. Work O(nC) for construction, O(n) decoding per query; temporary DP cell count (n+2)(C+1), capped at 150,000 before allocation. Cell count is a logical storage measure, not process RSS. Over-cap cases use packed dense directly. Rebuild only after new fixed exclusions and a fresh admission gate. No future revision count is supplied to the actor.

## Frozen workloads

Four arms: native reference, packed dense, eager atlas, delayed atlas (build after four observed queries under an unchanged fixed-exclusion scope). All memory begins empty per root/arm/workload. No cache sharing across roots. Native cold episodes: 12 TRAIN and 12 calibration roots per width (5,12,16), relevant and unrelated revisions; 576 executions across arms, full trace equality and independent host verification. Native widths above five are deterministic development extensions.

Public solver replay: widths 16/32/64/128, capacities 2n and 8n, 12 fresh underlying roots per cell; stable source s1 with 1/4/16/32 sequential revisions of s0, and a 16-query churn stream with a fixed-source change every fourth query. Revisions cycle candidates only when necessary, so longer streams may repeat exclusions; workloads are paired, not independent roots. 6,624 requests per arm (26,496 total); direct reference DP and feasibility/current receipt checks, no native host at these widths. Timing includes preparation, filtering, build, invalidation and fallback, and rotates arm order by root index. Record per-root CPU, builds, atlas uses, fallback, invalidation, rejected builds and peak DP cells. Compare against packed dense as primary speed baseline. No tuning on these results, no protected evaluation, API calls, training admission or default change. CPU timing descriptive.
