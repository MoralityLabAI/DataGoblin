# Partial separator cache under evidence updates

Source: https://github.com/MoralityLabAI/LoopedTransformers/tree/cec5535dbd5d9f7763530042ed74c5bbc7ef3968/experiments/logrank_bpd_20.

20 tests exact on-demand separator memoization under a logical retained-message cap of 16/64/256/1024KiB. All 360 admitted trajectories match exact recomputation across four batches and three evidence updates. Cache each unsigned message by graph/model version and directed edge; for a changed owner o, invalidate directions whose source-side component contains o. With fixed topology, unchanged source sides remain exact; lazily recompute missing messages. Use a new graph/model version when scopes or likelihood semantics change. No stale signed message reuse.

At 96D hubs/64KiB, cumulative requests times cold recomputation work per charged byte saves 22.0% counted arithmetic vs LRU, but is 3.9% slower. At 96D chains/16KiB, the heuristic saves 34.3% arithmetic and 29.4% elapsed time in this sample. At 96D hubs/1MiB, selective invalidation saves 12.3% arithmetic and 12.8% time vs flush. The 16KiB hub arms are slower than direct. All dense worlds exceed scope six before factor allocation. Three independent worlds per stratum, paired noise, single fixed-order timing; descriptive development data.

The next MMS candidate should count marginal work saved conditional on cached descendant messages rather than total cold subtree cost. Separate direct query demand from recursive miss-induced demand, use cheaper incremental eviction priority maintenance, and measure runtime including priority updates. Compare with exact LRU and flush on fresh workloads with changes in query popularity, update locality and update frequency. Validate exact outputs, graph/version invalidation, and every byte-ledger transition. Current logical charge excludes temporary contractions, policy metadata and actual RSS; instrument those for a true process-memory benchmark.
