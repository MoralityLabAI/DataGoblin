# Reusable separator-message memory for MMS

Source: https://github.com/MoralityLabAI/LoopedTransformers/tree/1e80b84527246fc38336b00831bdcd26287e3fe8/experiments/logrank_bpd_19.

19 compares exact per-query upward contraction, fully calibrated path reuse and source-batched path reuse. All methods use the same tree, local integer likelihood tables and evidence; all returned probabilities agree with an independent exact reference. At 96 dimensions, two-hub chains and 64 queries: 65.771ms direct, 32.640ms path, 22.489ms batch (setup, root or calibration and preflight included); batch reduces counted message arithmetic by 78.6%. It wins in all 36 admitted structured conditions at 64 queries. For four queries the amortized benefit is inconsistent. Workload deliberately includes common-source clusters. All 18 dense conditions exceed the scope-six cap and refuse.

MMS memory candidate: directed separator messages keyed by public factor-graph version, likelihood version, tree edge, scope and evidence epoch. Maintain explicit byte admission, cache hit/recomputation costs and message lifetime. For unchanged evidence, reuse off-path messages and batch queries by shared sources. On an evidence update, invalidate precisely those directed messages whose eliminated side contains the changed factor; recompute on demand. Cache eviction changes work but not exact answers if missing messages are recomputed from the corresponding factor subtree. No stale messages or hidden side information. These invalidation/partial-cache rules are proposed, not benchmarked.

Full cache object estimates at 96D average 205185 bytes for chains and 356418 for hubs. Conservative maximum preflight is 325432 and 596056 bytes respectively, excluding local factors, signed temporary messages and process allocator overhead. All benchmark full caches pass the 1MiB cap. At 256KiB the conservative rule rejects both 96D families; lower caps are admission diagnostics, not separate timed runs. Next compare partial caching by measured reuse value per byte, LRU and no-cache controls, with fresh repeated-query and evidence-update traces. Include true measured workspace and exact reference. No native MMS or DataGoblin integration or confirmation release.
