# MeTTa corpus and curation gym

**Repository:** `MoralityLabAI/DataGoblin`  
**Status (2026-11-22):** pinned source inventory and deterministic CPU research fixtures. Runtime MeTTa semantics, full corpus admission, trained-model performance, and native execution remain unverified.

The goal is to teach DataGoblin how MeTTa's declarative facts, pattern matching, rule chaining, types, and spaces can organize a research corpus. The first implementation puts evidence custody ahead of model-generated decisions. A learner may propose a curation plan; the existing DataGoblin etiquette policy and independent verifiers decide what is released.

## Generate curation exercises without any upstream checkout

Install the repository locally, then run:

```bash
python -m pip install -e ".[dev]"
python -m MeTTa.curation_gym --out runs/metta/curation
```

This produces **1,960 deterministic candidate exercises**: ten metadata/policy variants for each pinned source file. Every exercise contains a small MeTTa fact store and a `match &self` query. Variants cover intact provenance, unknown/restricted licenses, secrets, hidden reasoning, model weights, denied consent, deletion requests, unredacted personal data and absent provenance.

The learner sees a source envelope and MeTTa expressions. For training-candidate source families, `policy_reference` is generated by DataGoblin's actual `EtiquettePolicy` and includes the policy hash. Development and out-of-distribution cases omit teacher labels entirely.

These are **synthetic policy fixtures**. They teach a curation *decision proposal*, with statuses such as `DISCOVERY_ONLY` and `QUARANTINE`, rather than proving any upstream MeTTa program correct. No automatically generated answer is authorized as `VERIFIED_TRAIN`; the export's `training_ready` field remains false.

The generated data and manifest live under ignored `runs/metta/curation/`. A CI job runs the same CPU-only generator and publishes the resulting bundle as a GitHub Actions artifact.

## Collect real MeTTa source forms offline

Check out the three repositories at the catalog's *exact* commit hashes, then point the read-only collector at them:

```bash
python -m MeTTa.collect \
  --checkout hyperon_reference=/path/to/hyperon-experimental \
  --checkout metta_examples=/path/to/metta-examples \
  --checkout metta_storyworld=/path/to/metta-storyworld \
  --out runs/metta/intake
```

You can start with a single `--checkout`. The collector reads Git `HEAD` and validates each file against its recorded Git blob SHA and byte length. A modified checkout fails. The extraction phase never executes MeTTa, never invokes a network call, and rejects escaping symlinks. A lexical scanner handles parentheses, quoted strings, comments and evaluation prefixes.

Outputs:

- `forms.jsonl` stores source-file/line provenance, exact fragment hash, query/expression kind, proposed split and custody.
- `manifest.json` records SHA-256 digests, counts, and cross-split exact-duplicate collisions.

The source-file root stays attached to every derivative. Split assignment keeps source-family modules together; the owned Storyworld corpus is held out. Cross-split identical atoms are quarantined pending steward review. Source metadata cannot give a form verified semantic status.

## MeTTa teaching fixture

`seed/curation_graph.metta` gives an original native MeTTa fact/query example that joins source, license, provenance, split and custody atoms. It proposes relevant candidates through `match &self`. The graph never admits records, removes data or prunes an evaluation branch. Run it with the pinned Hyperon interpreter and archive the native execution receipt before turning any query-output example into runtime-grounded supervision.

## Looped-transformer SFT curation program

[**MeTTa-SFT-02**](LOOPED_SFT.md) adds six synthetic research-data curation families with explicit next-edit, evidence-preference, native-shaped MeTTa query and stop targets. Its independent bounded Python oracle produces a reproducible 3,072-root default curriculum while preserving a maximum of four presentations per root and keeping development/test/novel conflict worlds unlabeled. The generated rows can be exported into LoopedTransformers' `instruction/input/output/metadata` schema as an alternate view of the same examples.

```bash
python -m MeTTa.looped_sft build --roots-per-family 512 --out runs/metta/looped_sft
python -m MeTTa.looped_sft audit --out runs/metta/looped_sft
```

These are synthetic candidate supervision records. Native MeTTa execution and trained-model improvements remain future validation gates.

## Next curation curriculum

| Exercise | Learner task | Required check |
| --- | --- | --- |
| Atom indexing | Convert MeTTa source forms into line-addressed, hashed atoms | Exact source/blob/line replay |
| Graph retrieval | Build and query `Source`, `Lineage`, `License`, `Evidence` facts | Native Hyperon query comparison |
| Evidence deduplication | Recognize the same lineage across repeats and repairs | Origin SHA and split audit |
| Policy critique | Propose `REJECT`, `QUARANTINE` or `DISCOVERY_ONLY` and justify actions | `EtiquettePolicy` decisions |
| Rule composition | Apply typed rules to build a minimal research packet | Native MeTTa plus independent verifier |
| Counterexample repair | Diagnose a failed `match` or invalid curation suggestion | Fresh independent replay |

The immediate scale path is source-pinned harvesting followed by independently checked native MeTTa query traces, with the RLT gym recording failed proposals and successful repairs. Reuse of derivative presentations stays inside DataGoblin's existing root-level repeat cap. The model's own explanations remain attributed hypotheses.
